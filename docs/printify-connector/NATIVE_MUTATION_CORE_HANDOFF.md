## What is implemented in this companion

`Preparation/ProviderMutationResponse::observe(intent,body,status)` is a pure provider-specific observation boundary for IMAGE_UPLOAD, PRODUCT_CREATE, PRODUCT_UPDATE and PRODUCT_PUBLISH. It validates the original metadata before dropping unrelated provider fields, checks explicit shop contradictions, bounds JSON to 1 MiB/depth 32, rejects executable/non-JSON objects, and emits only minimized metadata. Known upload dimensions, filename, optional size/MIME, product/blueprint/provider/variant IDs and update identity are checked through existing strict validators. Publication 200 is asynchronous PUBLISH_PENDING, never verified publication. Non-200/timeout observations are UNKNOWN; provider error bodies are discarded; no retry is authorized. No transport, secret lookup, store or receipt signer exists here.

Every observation explicitly has trusted_receipt=false, network_request_permitted=false, external_execution_authorized=false and retry_permitted=false. It contains no receipt_hash, event, fence or epoch. An observation cannot be imported as a trusted receipt. The existing ProviderReceipt validator still verifies the original exact envelope/hash before metadata use; no attested receipt is rewritten or rehashed during projection. The core must perform secret-aware sanitization while in credential custody before releasing data; this pure helper cannot recognize an unknown secret appearing as an otherwise valid identifier.

`VersionedMutationHost::responseEvidence` now revalidates current core authority after receipt retrieval and validation, before returning protected evidence. A deterministic synthetic core revokes during RECEIPT_READ: the earlier adapter returned an array, the corrected adapter denies. This narrows a read-disclosure window; it is not an atomic final-dispatch fence.

Provider fixtures are explicitly synthetic. They do not establish FL-03/FL-04 artwork, native-layer, provider geometry, rights or commercial certification. No new core schema, credential vault, approval store, shop mapping, scheduler or sender is added.
