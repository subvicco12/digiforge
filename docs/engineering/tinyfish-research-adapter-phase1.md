## Implemented bounded software

`includes/Research/TinyFishResearchContract.php` is an offline simulator/contract, not a connected browser. It has no HTTP/CDP client, routes, hooks, provider credentials or activation code. It never authorizes external execution, supplier certification or API identity certification. Approval/rate/session SHA fields are opaque proposed metadata, not authentication or proof of an owner signature. A future controller must independently authenticate the actor, validate current `ShopAccess`/owner authority and binding evidence, and preserve STOP ALL/external lock/automation interlocks. Existing catalog GET grants do not authorize TinyFish browser or profile operations.

The contract requires explicit account/session/scope hashes, integration/environment/shop identity, expiry, request quota, session duration, rate provenance and monetary ceiling. Only `personalized_pod` is accepted; Digital is independent and Standard POD/Jewelry are deferred. Session duration is bounded to 900 seconds, request count to 100, with ten intents per rolling minute and monotonically increasing intent times. Full-duration estimated browser cost must fit the explicitly supplied ceiling; no approved default amount or live rate is installed. Tests use synthetic values. Every result remains offline/unreviewed.

Checkpoint HMAC covers the exact account, environment, provider-shop, integration, session and scope revision plus hash-chained event history. Changed state, wrong signing key, changed expected scope, expiry or supplied revocation deny resume. Completed intent fingerprints deny duplicate intents within that checkpoint lineage. The signer is supplied by a trusted caller, never a request body; object debugging omits it and serialization is rejected. **No durable store, cross-process replay protection or atomic monetary reservation is implemented here.** A future persistence layer must compare-and-swap the latest revision/hash and reserve quota/cost in the same transaction before dispatch; old signed checkpoints must not be accepted merely because their HMAC remains valid. Unknown dispatch/session creation outcomes require operator reconciliation, not new sessions or automatic refunds/retries.

Public-document GET intents are narrowly allowlisted to canonical `https://printify.com/app/products/{id}/{brand}/{slug}`, `/app/print-provider/{id}/{slug}` and `/shipping-rates/{slug}/`. No query, fragment, arbitrary host, port, userinfo, encoded path traversal or payload is admitted. There is no free-form goal, click, typing, JS execution or login action. Orders, editor, settings, store management and all POST/PUT/PATCH/DELETE operations are denied. XHR, fetch, WebSocket, frames, service workers, downloads and other subresources are not admitted by this first contract. A document allowlist is not a working or proven complete browser/network firewall.

Structured extraction accepts only bounded typed fields: family/destination, supplier IDs, pixel geometry/DPI/bleed/safe zone, USD research prices/shipping and reported eligibility. Unknown values stay UNKNOWN, and EU group research cannot become country eligibility. Evidence binds the scoped synthetic extraction event, exact product source URL/blueprint, absolute UTC observation timestamp and normalized digest. It contains no raw HTML, arbitrary text, screenshots, cookies, CDP URLs, profile IDs, credential headers or session storage. Its digest is integrity evidence for supplied synthetic fields, not proof of supplier authenticity, file bytes or licensed artwork. Mockup rights, API certification, supplier certification and live authority never become true.

## Official API findings and design consequences

Sources below are public official documentation retrieved on 2026-10-16; documentation is not contractual account-specific approval.

- [Authentication](https://docs.tinyfish.ai/authentication): REST uses `X-API-Key`; MCP uses OAuth 2.1. No key was obtained/read/created, and no MCP connection was activated. No credential-printing examples are adopted.
- [Browser API](https://docs.tinyfish.ai/browser-api) and [reference](https://docs.tinyfish.ai/browser-api/reference): `POST https://api.browser.tinyfish.ai` creates an isolated session and returns `session_id`, `cdp_url`, `base_url`; DELETE terminates it. Startup can take 10–30 seconds. Supplying a startup URL navigates before the controller can install interception: a future safe controller must create without target navigation and prove guards installed first. Use `cdp_url` for CDP, not `base_url`.
- Browser timeout is **inactivity**, not a hard spend limit. Overview lists plan maxima of 15/60 minutes; reference permits `timeout_seconds` 5–86400 subject to account limits. Actual account limits and billing rounding are UNKNOWN. A separate wall-clock watchdog and narrowly authorized teardown must enforce the agreed budget; failed/unknown DELETE outcomes remain unresolved, not confirmed termination.
- [Browser Context Profiles API](https://docs.tinyfish.ai/agent-api/browser-context-profiles) and [overview](https://docs.tinyfish.ai/key-concepts/browser-context-profiles): profiles save cookies/local/session storage. Setup returns a temporary CDP session plus expiry; owner may sign in manually, then save or cancel. Saved state is documented for Agent `use_profile:true` with explicit `profile_id`. It is not the `browser_profile` runtime mode. The inspected docs do not establish a direct Browser API restore mechanism with our required network restrictions. Do not assume `profile_id` can be passed to the direct Browser API.
- Do not use default/shared profiles, exported cookies, Vault credential repair or autonomous login. TinyFish Vault/profile storage is a separate trust boundary. Provider-side encryption/key custody, retention, recordings, screenshot/log controls, deletion guarantees, region and authorized operator access remain unverified for this account. Secrets must never enter DigiForge artifacts, prompts, logs, issues or repository. No session URL is an ordinary public artifact: treat CDP/devtools/interactive links as secrets.
- Public pricing says run screenshots/logs/source URLs are retained/addressable; enterprise includes audit/VPC capabilities. Neither statement proves sufficient control for private Printify research. Data handling/security review is a blocker, not an assumed feature.

## Technical guard and resumability integration contract (not implemented live)

1. Separate owner login/setup mode from automated research. Setup necessarily uses auth mutations and needs separate narrowly scoped authorization; automated research must never enter the login flow, type passwords, solve/bypass CAPTCHA or repair sessions with Vault. If authentication/bot checks appear, pause and ask owner to use the approved private interface.
2. Before any Printify navigation, enforce all-request, all-frame interception at the browser/network boundary, disable service workers/popups/WebSockets and inspect each redirect. The remote endpoint/firewall and account/profile isolation must be attested. Prompt instructions alone are insufficient; free-form Agent runs remain blocked.
3. Add only verified static/catalog endpoints needed for the page, with exact origins/methods/content types and bounds. Browser read POSTs remain denied until separately reviewed for exact endpoint, schema and absence of mutations; never grant generic POST permission. Existing Printify catalog GET exception does not cover browser session POSTs or profile writes. Downloaded files require a distinct size/type/path/hash/rights boundary. This phase downloads none.
4. Persist non-secret checkpoint metadata and normalized evidence in protected shop-scoped storage with the existing audit and shop-authority architecture. Use independently provisioned signing/encryption keys; CAS current revision, one-shot request IDs and quotas; protect concurrent worker leases and reserve conservative costs before dispatch. Atomic budget controls must reuse the existing AI/provider-cost boundary where applicable without depending on deferred revenue/profit/Finance work. No authoritative provider charge is invented.
5. Resume only with current actor/shop/account/integration/session/profile revision, approval, rate and unexpired lease. Do not silently migrate a checkpoint to another shop/session/region or replay an uncertain request. Hard-stop on revoked assignment/profile, stale provider identity, expiry, 401/402/403, missing/changed tariff or uncertain cleanup.
6. Audit allowed/denied intent fingerprints, timestamps, identity/scope hashes, source and result digests, retry/resume status and explicit review state. Never ingest arbitrary provider error text, raw DOM or unredacted screenshots. Preserve private source evidence separately with access controls and byte hashes. Redacted public summaries are not substitutes for protected originals.

## Costs and owner steps

[Official pricing](https://www.tinyfish.ai/pricing), observed 2026-10-16: Browser **USD 0.002/minute**, Agent **USD 0.016/step**; advertised Search/Fetch free within rate limits. Wallet and legacy-account terms differ. Published concurrency is 5 Browser sessions / 2 Agent runs; we require one initial research lease, not automatic use of those maxima. Wallet exhaustion is not a guaranteed hard stop; docs say existing Agent runs can finish. No wallet deposit, auto-reload or paid call was initiated.

Illustrative estimates only: 10 browser minutes = USD 0.02; five families × six market buckets × two minutes = 60 minutes = USD 0.12 browser usage. These are not measured runtimes, guaranteed upper bounds, approved budgets or supplier charges. A 25-step Agent run would be USD 0.40 at the published rate, but Agent is intentionally not wired. Agent/browser billing overlap, startup/rounding, private retention and account-specific terms require confirmation before an authoritative reservation. No default spending ceiling is installed.

Minimum owner steps **after separate explicit authorization**, not now:
1. Approve one exact shop/account/environment, research scope, duration/request/cost ceilings, retention/security conditions and the narrow session/setup/cleanup operations under existing locks. No general Printify activation.
2. Use an approved private TinyFish hosted setup interface (or independently approved secure interactive controller) to sign in directly to Printify and complete MFA. Select the Etsy-connected DigicraftifyShop, dashboard ID 28930593; keep the separate Printify-hosted store distinct. Never send passwords, cookies, API keys or session links in chat. No token creation is authorized by phase 1.
3. Owner must approve who may use/revoke the dedicated profile, its expiry and retention. Existing dashboard evidence does not certify API ownership or authorize browser automation. If the hosted setup interface cannot meet these controls, stop rather than export cookies.

Current blocker list: no live authorization, approved monetary ceiling/account tariff evidence, credentials/profile provisioning, attested network interception, secure owner sign-in path, verified provider privacy/retention controls, direct-browser profile restore contract, durable CAS/lease/quota/cost persistence, and real supplier/licensing/geometry evidence. All remain fail-closed. No generic Agent browser or provider transport is connected. Existing 246/268 acceptance classifications are unchanged.
