## Reliability and uncertainty

Every physical attempt reserves shared account quota under InnoDB transaction/advisory lock. Separate shop credentials sharing a verified external account consume one account budget. Quota identity is not derived solely from a shop ID. Counters reject malformed storage, outer transactions, duplicate attempt identities and unavailable locks. 429 applies bounded Retry-After1..3600; authentication/authorization failures cool down300s; three transport/5xx failures open60s circuit. Safe GET retries max3 and100/200ms delay, each explicitly included in a newly reviewed read budget. 429/Retry-After pauses without sleeping until provider recovery. Catalog preserves its ten-request grant and no implicit retry expansion. Mutations never retry automatically. Transport has TLS verification, zero redirects, bounded timeout20s (catalog10s), 1MiB+1 truncation detection, fixed API host/path and required User-Agent. Raw credentials/request bodies are not logged.

Permanent creation claims prevent duplicate intent dispatch across reauthorization or connection revision. An unknown image/product/order result remains UNKNOWN. An unrelated product read cannot resolve an unknown creation. Complete order page coverage requires identical page size/last page, contiguous pages, full intermediate pages and unique order IDs. Missing/partial/inconsistent observations never establish completeness. Page-number observations are not an atomic supplier snapshot and do not prove which call caused a state. Exact source receipt hashes remain attached; no readback gives retry authority. Reservation22 is not queried, retried or modified.

## Private webhook configuration and boundaries

`DIGIFORGE_PRINTIFY_WEBHOOK_CONFIG` must refer to a canonical regular non-symlink JSON file outside ABSPATH, mode0400/0600, <=64KiB. Entries keyed32lowerhex contain exact `site` (home_url), `shop_key`, `integration_id`, `provider_shop_id`, unique `current_secret`>=32bytes. Optional `previous_secret`, `rotation_started_at`, `previous_valid_until` permit bounded<=24hour rotation grace, not arbitrary old-key acceptance. Callback derives from WordPress `rest_url` and must be HTTPS. REST identity comes from route parameters, never body/query overrides. No production secret/configuration was created. Existing HMAC/secret infrastructure for unrelated purposes remains intact.

Ingress accepts authenticated supplier evidence only and durably stores a minimized, sealed event reference. It does not authorize business transitions. Isolated fakes test transaction rollback, duplicate/conflict, owner access and dead-letter behavior. Valid late deliveries beyond the local24hour freshness window are deliberately denied and require governed fresh readback; no timestamp-window widening or automatic replay.
