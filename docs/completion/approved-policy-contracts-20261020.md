Typed v2 rules must exactly match `ApprovedAcceptancePolicy::rules`; a signed generic or altered payload cannot substitute another formula or authority.

The existing authenticated read-only REST projection includes `policy_evaluation` only for an explicitly requested matching environment; foreign environments remain UNKNOWN. The selected-shop portal prints escaped JSON, enforces matching shop/criterion/scope/environment, and forces all certification/execution flags false. Parent status/evidence remains UNKNOWN/UNVERIFIED even when a local calculation succeeds. No provider/source-record adapter is invented: `source_records` are pinned declarations inside the reviewed snapshot, **not verified immutable provider records**. A review of a snapshot is not proof of provider authenticity, licensing or linguistic quality.

## v2 input and interpretation

Outer fields stay `version`, `criterion`, `scope`, `workflow`, `definition`. Definition fields are exactly `policy`, `environment`, `subject`, `period_start`, `period_end`, `source_records`, `observations`. Policy is the exact approved machine-readable rule returned by `rules()`. Subject is explicit SHOP (null narrower identities), SUPPLIER (exact supplier) or PRODUCT_VERSION (exact product and version, optional exact supplier). Timestamps are absolute and form a half-open window. Source references retain the existing local shop/reference/SHA form. Missing observations or source records yield UNKNOWN. Existing storage caps (32 KiB snapshot, 100 elements per array, depth 12) prevail over any evaluator loop bound. These are engineering resource bounds, not new commercial limits.

Metrics require explicit completeness flags for visits/orders/units/defects. Typed VISIT, ORDER and fulfilled UNIT rows carry exact shop/product/version/supplier/source/time identities. Rows outside scope/window, unmatched attribution or conflicting duplicate identities reject; byte-equivalent duplicate units count once. Orders without visit attribution do not enter conversion numerator. Units require matching in-cohort order provenance; this deliberately does not infer older-order fulfillment cohorts. Timeliness and exceptions expose counts with named denominators, **not an unapproved rate formula or weighted score**. Zero denominator and incomplete/unreviewed populations return UNKNOWN/null, while supported complete zero event counts remain zero. No Finance dependency, calculation or field is added.

Feedback corrections preserve all prior rows in the signed snapshot/history; revisions must be contiguous and previous digests match, with immutable order/product/version/shop/supplier attribution and nondecreasing observation time. No customer wording, contact data or free-form allegations are accepted or projected. The independently authorized reviewer reviews the whole local snapshot; CONFIRMED remains a reviewed local declaration, not provider certification.

Seam/text/font/native evidence digests remain declarations. Actual immutable artifacts and provider origins must still be verified through existing artifact/ownership/certification mechanisms. No matching hash alone supplies rights, language sign-off, supplier readiness or release authority. Existing FC01 assets/layout and v1 source hashes are untouched. Shops 3/4 remain deferred; Digital acquires no POD dependency.
