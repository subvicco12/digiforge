# U3 QA Repair Cycle

Approved candidates may be retried without mutating Gate 1 approval. Each repair attempt receives a unique run key so production plans, specs, revisions and QA evidence are fresh. Product development uses a stable candidate/shop development key so the existing product/version identity is reused rather than duplicated.

Every generated customer package includes a machine-readable delivery manifest and a provenance record. Production prompting rejects fake Canva links, placeholder URLs, fake QR destinations, incomplete HTML and unsupported marketing claims.

Repair execution remains internal only. Etsy draft/publish, Printify, Gelato, order/fulfillment and GST/tax actions are not invoked. QA remains fail-closed and Product Approval remains a human gate.
