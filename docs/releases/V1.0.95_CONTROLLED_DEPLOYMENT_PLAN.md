## Scope
This release completes the governed Master 500 v2 persistence seam. It binds the reviewed v2 research/migration workbook identity, requires the exact immutable v1 catalog parent before v2 persistence, preserves one-to-one v1→v2 lineage in existing catalog tables, and records v2 only as a MIGRATION_CANDIDATE.

No database schema migration is required.

## Safety boundary
The current STOP ALL / activation / automation posture must be preserved throughout deployment.
- STOP ALL remains authoritative.
- Installation does not authorize activation or automation.
- A persisted v2 migration candidate does not replace or promote the immutable v1 baseline automatically.
- production_authority remains false.
- promotion_authorized remains false.
- No Etsy publish, POD provider production, retry, money movement, refund, GST/tax filing, or other external action is authorized by catalog ingestion.
- An unknown transaction commit result requires reconciliation before retry.
