# DigiForge v1.0.102 Controlled Deployment Plan

Candidate: DigiForge 1.0.102
Expected schema after migration: 23

## Scope
This release isolates bounded operator-facing database reads from stale prior database error state. Independent finance, integration, queue, audit, order, catalog, exception, and render-evidence reads are classified from their own current query result rather than inherited errors.

## Safety invariants
- The current STOP ALL / activation / automation posture must be preserved across installation.
- External execution authority remains NO.
- Historical external-action evidence MUST NOT be cleared or rewritten.
- Do not manually set schema-version options.
- UNKNOWN or UNAVAILABLE evidence is not PASS.
- No Etsy publish, POD production, provider dispatch, retry, replay, catalog promotion, money movement, tax filing, or other external execution is authorized.

## Preserved deployment controls
- Rollback means restoring the last compatible audited plugin + database checkpoint together.
- The body-key exception applies only to this local raster-and-QA workflow.
- Existing mutation routes retain their required `Idempotency-Key` header contracts.
- QA success is not human approval.

## Release gate
Deployment is BLOCKED unless the exact candidate head passes the Engineering & Safety Audit and the audited manifest binds plugin version 1.0.102, schema 23, and exact commit SHA with production_activation_authorized=false.
