The new exact baseline overlay recognizes actor1 only through audited Store profile + valid DigiForge session + all live native authority/capability checks. It shows authorized selected-shop/all-shop assignment evidence and links to existing audited User Management. It issues no raw grants or renewals on GET and changes no profile revisions.

The legacy ENROLL path is denied for EVERY actor; actor1 legacy POST mutations are denied in favor of modern shop/module profile management. No competing owner or alternate owner trust can be created. Existing independently signed DELEGATE contracts are retained only for unprofiled legacy delegates with native exact-shop management authority; signed OWNER records cannot become new owners. Managed Admin/Operator/Viewer profiles cannot use legacy raw mutation to bypass module scoping. Missing/expired/revoked sessions or native receipts do not fall back to a signed root. No new keys, host approval or reenrollment needed for an already valid owner. Existing1.0.103.12 authentication/renewal code is unchanged.

## Optional Action Scheduler decision

Action Scheduler is NOT required for portal login, Global Primary Owner access, administrative reads or core inert Queue/Scheduler. Existing ProductFactory scheduling has its own WordPress-cron fallback and execution gates; that implementation is unchanged. WP cron AVAILABLE is evidence of readable cron metadata, not proof automation is armed. No dependency is bundled, installed, activated or initialized by this update.

Prior Scheduler::available used function_exists alone. Prior ScheduledTaskReadModel could query library functions before initialization. New shared helper distinguishes ABSENT, UNINITIALIZED, INCOMPATIBLE and UNAVAILABLE from AVAILABLE. It verifies required APIs/constants and initialization, reads only8192bytes of the active library bootstrap header through its official plugin_path API, checks the active stable version against registered version and fails closed on unavailable/mismatched evidence. Upstream has no active_version method; none is called. Metadata or task-query failure never creates empty-success evidence. Existing query_state AVAILABLE/UNAVAILABLE and cron adapter contracts remain compatible; detailed dependency evidence is additive. The owner automation page shows library/API detail separately from task evidence; API readiness never grants scheduling/retry/provider permission.

Supported read-only API contract: stable Action Scheduler >=3.5.0,<5.0.0 with required functions/store constants and is_initialized()===true, actual active header matching registration. APIs verified against official3.5 and current4.2 sources, including get_scheduled_actions, enqueue API, status constants, initialization, plugin_path and version registry. This is NOT certification of all third-party releases, plugin combinations or WordPress/PHP versions. Versions outside the verified boundary are conservatively unsupported, not proven broken. Production acceptance only established old query UNAVAILABLE; it did NOT identify whether the library is absent/uninitialized/incompatible. Do not claim production ABSENT without the new bounded evidence.

Official source references: https://actionscheduler.org/api/ ; https://github.com/woocommerce/action-scheduler/blob/3.5.0/classes/abstracts/ActionScheduler.php ; https://github.com/woocommerce/action-scheduler/blob/trunk/action-scheduler.php ; https://github.com/woocommerce/action-scheduler/blob/trunk/classes/ActionScheduler_Versions.php .
