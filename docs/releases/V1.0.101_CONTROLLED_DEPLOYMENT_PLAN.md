# DigiForge v1.0.101 Controlled Deployment Plan

Candidate: DigiForge 1.0.101
Expected schema after migration: 23

## Scope
This release hardens governed Master 500 v2 evidence integrity. Parent evidence queries start from a clean database error boundary, and persisted v2 readiness requires the stored catalog fingerprint to exactly match the fingerprint embedded in migration metadata. Conflicting evidence remains blocked for reconciliation.

## Safety invariants
- Preserve the current STOP ALL / activation / automation posture; it must be preserved across installation.
- External execution authority remains NO.
- Historical external-action evidence MUST NOT be cleared or rewritten.
- Do not manually set schema-version options.
- UNKNOWN or UNAVAILABLE evidence is not PASS.
- No Etsy publish, POD production, provider dispatch, retry, catalog promotion, finance, tax, or other external execution is authorized.

## Preserved deployment controls
- Rollback means restoring the last compatible audited plugin + database checkpoint together; never mix incompatible code and persistence state.
- The body-key exception applies only to this local raster-and-QA workflow.
- Existing mutation routes retain their required `Idempotency-Key` header contracts.
- QA success is not human approval and creates no production execution authority.

## Release gate
Deployment is BLOCKED unless the exact candidate head passes the Engineering & Safety Audit and its audited package manifest binds plugin version 1.0.101, schema 23, and the exact commit SHA with production_activation_authorized=false.
