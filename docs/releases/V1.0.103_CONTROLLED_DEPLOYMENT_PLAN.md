# DigiForge v1.0.103 Controlled Deployment Plan

Candidate: DigiForge 1.0.103
Expected schema after migration: 23

## Scope
This final 1.0.103 convergence candidate includes the certified fail-closed Approval Inbox/provenance work, governed Product Factory AI generation boundary, and Stage-F dashboard attention-evidence correction. Product Factory generation requires authoritative shop policy/preflight and deterministic attempt identity; monetary AI budgets fail closed when truthful actual-cost attribution is unavailable. The dashboard initializes its attention evidence before rendering and still presents unavailable evidence as UNAVAILABLE rather than zero.

## Safety invariants
- The current STOP ALL / activation / automation posture must be preserved across installation.
- External execution authority remains NO.
- Historical external-action evidence MUST NOT be cleared or rewritten.
- Do not manually set schema-version options.
- UNKNOWN or UNAVAILABLE evidence is not PASS or CLEAR.
- No Etsy publish, POD production, provider dispatch, retry, replay, catalog promotion, money movement, tax filing, or other external execution is authorized.

## Query-state acceptance
- Each evidence query clears stale database error state before execution.
- A current-query error is explicitly UNAVAILABLE.
- A later independent query may succeed after an earlier failure, but the aggregate remains PARTIAL_UNAVAILABLE until all required evidence is available.
- Provenance correlation evidence is not persisted from incomplete outcome/closure/acknowledgement reads.
- Attention totals cannot claim an authoritative zero when provenance evidence is unavailable.

## Preserved deployment controls
- Rollback means restoring the last compatible audited plugin + database checkpoint together.
- Existing mutation routes retain their required `Idempotency-Key` header contracts; confirmed-success identities are never reused.
- The body-key exception applies only to this local raster-and-QA workflow; it does not relax header-key requirements on external mutation routes.
- QA success is not human approval.
- Deployment does not change production automatically.

## Release gate
Deployment is BLOCKED unless the exact candidate head passes the Engineering & Safety Audit and the audited manifest binds plugin version 1.0.103, schema 23, and exact commit SHA with production_activation_authorized=false.
