# DigiForge v1.0.100 Controlled Deployment Plan

Candidate: DigiForge 1.0.100  
Expected schema after migration: 23

## Scope
This release isolates read-only AI policy and cost evidence query states. It resets database error state at each independent query boundary and fails closed when either AI cost totals or breakdown evidence is unavailable. It does not add or grant external execution authority.

## Safety invariants
- Preserve the current STOP ALL / activation / automation posture; it must be preserved across installation.
- External execution authority remains NO.
- No Etsy publish, POD production, provider dispatch, retry, catalog promotion, money movement, or tax action is authorized.
- Historical external-action evidence MUST NOT be cleared or rewritten.
- Do not manually set schema-version options.
- UNKNOWN or UNAVAILABLE evidence is not PASS.

## Release gate
Deployment is BLOCKED unless the exact candidate head passes the Engineering & Safety Audit and its audited package manifest binds plugin version 1.0.100, schema 23, and the exact commit SHA with production_activation_authorized=false.

## Preserved deployment controls
- Rollback means restoring the last compatible audited plugin + database checkpoint together; never mix incompatible code and persistence state.
- The body-key exception applies only to this local raster-and-QA workflow.
- Existing mutation routes retain their required `Idempotency-Key` header contracts.
- QA success is not human approval and creates no production execution authority.
