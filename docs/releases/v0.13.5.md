# DigiForge v0.13.5

Runtime packaging correction for the U3 Product Factory repair path.

## Root cause
The deployed v0.13.4 ZIP diverged from the merged repository implementation: its expanded Orchestrator referenced `$packageVariant` inside the product/marketing asset loop before that variable was assigned. Under PHP 8.3 this produced a null argument for the strictly typed `produceOne(..., string $variant)` parameter and Action Scheduler failed before creating repair asset specs.

## Release rule
The v0.13.5 production artifact must use the merged repository behavior or define the repair asset variant before the asset loop. The variant is always a string: `repair-{planToken}` for repair runs and an empty string for initial runs.

## Safety invariants
- DB schema remains 13.
- Product/version identity remains stable across repair runs.
- Repair production-plan and asset identities remain run-scoped and deterministic.
- Gate 2 remains human-controlled.
- Etsy Draft/Publish, Printify, Gelato, order automation, and GST automation are not activated.
- External actions remain disabled during Product Factory repair execution.
