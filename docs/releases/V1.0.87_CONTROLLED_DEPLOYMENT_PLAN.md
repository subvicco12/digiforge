# DigiForge v1.0.87 Controlled Deployment Plan

## Certified candidate

This candidate releases the governed local raster-and-QA execution surface added after v1.0.86. It combines approved-SVG derivation with deterministic PNG QA while preserving the existing human-approval and external-action boundaries.

- Candidate: DigiForge 1.0.87.
- Expected schema after migration: 23.
- Install only an Engineering & Safety Audit artifact whose release manifest commit equals the exact audited candidate head.
- Read production immediately before change; never infer installed state from repository state.

## Hard pre-install gates

Deployment is BLOCKED unless all are evidenced immediately before installation:
1. Health/readiness record the current STOP ALL / activation / automation posture and effective capability switches; preserve that posture unless a separately governed safety action requires revocation.
2. Historical external-action evidence remains intact, including confirmed-success operations and failed/UNKNOWN evidence.
3. A fresh retrievable production database backup and compatible rollback plugin/database checkpoint are available and verified.
4. The v1.0.87 ZIP checksum and release manifest verify plugin 1.0.87, schema 23, the exact audited commit, external_actions_performed=false and production_activation_authorized=false.
5. Queue/audit health is verified and no unresolved UNKNOWN becomes retry permission.

Historical external-action evidence MUST NOT be cleared or rewritten.

## Migration boundary

Do not manually set schema-version options. Schema remains 23. Abort on migration error, unexpected effective capability, missing table, audit failure, queue corruption, checksum/manifest mismatch, or unexpected external mutation. Rollback means restoring the last compatible audited plugin + database checkpoint together.

## Governed raster-and-QA boundary

The new authenticated `POST /digiforge/v1/production/revisions/{id}/rasterize-and-qa` workflow is local-only. It requires a bounded JSON `operation_key` because the connected execution surface cannot forward custom headers. That key is processed through DigiForge's existing durable idempotency reserve/complete guard.

This body-key exception applies only to this local raster-and-QA workflow. Existing mutation routes retain their required `Idempotency-Key` header contracts. It does not weaken Etsy, POD, publication, fulfillment, payment, tax/GST, or other external-operation idempotency.

The workflow must:
- revalidate an APPROVED SVG source and protected source integrity;
- create/reconcile a distinct PNG derivative without mutating the approved release bundle;
- run deterministic AutomatedQa against the protected PNG;
- persist each QA check;
- transition the derived revision only to QA_PASSED or QA_FAILED;
- return approval_required=true;
- perform no external action.

QA success is not human approval. The derived revision cannot become authoritative listing media until the required explicit human approval is recorded.

## Product #25 / Listing #1 boundary

After deployment verification, Product Version #25 revision #469 may be used only if its authoritative APPROVED state, exact image/svg+xml MIME, protected storage reference and checksum still match current evidence. A successful local derivative/QA operation does not itself change Listing #1, Release Bundle #1, Etsy Intent #1, or publication authority.

Before any Etsy image attachment, the derived PNG must be QA-passed and explicitly approved and all listing/package/release readiness evidence must be revalidated. If authoritative payload/readiness evidence changes, stale approval cannot be reused.

Never repeat confirmed-success CREATE_DRAFT operation #2 or UPLOAD_FILE operation #6. Failed publish operation #7 remains immutable historical evidence. ATTACH_IMAGE requires its own fresh external-operation idempotency key and UNKNOWN requires reconciliation before retry. Publish may be retried only after confirmed image attachment and current publication authorization. No POD production is authorized by this release.

## Post-install verification

Verify plugin 1.0.87, schema current=expected=23, pre-install STOP ALL / activation / automation / effective-switch posture preserved, queue/audit healthy, historical external-action evidence preserved, and no external mutation caused by install/migration.

## Completion boundary

Successful deployment proves only that the certified v1.0.87 code is installed and the governed local raster+QA workflow is available. It grants no media approval and no new Etsy/POD/external authority.
