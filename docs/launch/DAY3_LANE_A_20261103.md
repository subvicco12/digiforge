## Actual implementation

`DesignFactoryRepository` now requires a separately persisted human approval of an exact Day2 source-linked selected concept. Selection alone, a client approval flag, a prompt, a missing source or an unknown hash cannot prepare a design. The approval binds source context, recipient/occasion review, actor and timestamp. Source/specification/asset/review/revision records are immutable and parent-linked; edit/reject does not overwrite old bytes or decisions.

Detailed specifications include the approved concept and source identities, composition/layout instructions, typography hierarchy and licensing reference, explicit palette, asset requirements and named nonoverlapping native text/image reservation rectangles. Rectangles must fit the canvas; they are operator instructions, not supplier safe zones. Family adaptation requires the corresponding selected concept/profile, with new selection and review rather than inherited artwork approval.

Technical profiles are limited to the blueprint's FL-03 mug2475×1155 and FL-04 poster2418×3018 at300dpi, with existing draft references preserved. Supplier bleed and safe margins remain null; supplier certification remains false. No supplier variant, SKU, provider placement, shipping, listing or economics data is invented or changed.

The image-provider interface is server-owned and testable. The installed fallback explicitly reports NO_AUTHORIZED_IMAGE_PROVIDER. Production code makes no image-provider request; STOP ALL/effective AI/product-development capability checks precede dispatch, and approved future adapters get one immutable attempt per specification with no automatic retry. A provider must return actual editable SVG, optional separate PNG bytes and bounded provenance. Raster-only, malformed or extra-authority output is rejected. A model prompt/specification is not finished artwork, and PNGs are never called editable SVGs.

Manual original artwork intake is working. SVG is structurally validated through the existing Day1 contract, requires an exact viewBox/canvas and at least one drawing element, rejects active/external content, and is bounded to60000 raw bytes for B's existing guard. No file paths or remote asset URLs are dereferenced. Accepted PNGs are complete CRC-checked non-interlaced8-bit grayscale/RGB/alpha images with valid color metadata, bounded compressed/decompressed data, exact canvas size and embedded300dpi density. Unsupported/indexed/animated/JPEG assets are rejected. PNG bytes are stored in non-autoloaded shop-scoped content-addressed options; reads verify bytes/metadata again. Maximum2MiB per PNG,3 supplemental PNGs. PHP/web-server POST limits also apply; no runtime limits were changed.

Human review records nine explicit criteria: visual distinctiveness; buyer intent/gifting; typography/composition; personalization readability; family adaptation; commercial originality; print geometry compatibility; originality/licensing; mockup review. These are human attestations, not AI quality scores or legal/supplier certification. Every criterion must pass for APPROVE; failed criteria can be recorded for REJECT. A durable rationale/review intent and authoritative per-asset receipt precede Day1 approval. Failed receipts/decisions remain unconfirmed and cannot hand off. Review concurrency/outage cannot overwrite an existing decision.
