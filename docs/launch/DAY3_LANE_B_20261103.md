## Storage decision

AssetStorage confines real paths but does not resolve shop ownership and relies
on .htaccess for direct-web denial. LocalAssetProducer accepts a numeric product
version rather than an approved shop/artwork binding. Neither is sufficient by
itself to introduce a new public-file reference boundary.

Reuse the existing durable OpportunityDesignRepository storage instead. The new
explicit reference entry reads current authenticated shop-scoped immutable artwork,
verifies its original record SHA256, approval and SVG checksum, then emits a compact
reference instead of inline bytes. No file write, public URL, symlink following,
remote fetch, rasterization or increase to the existing inline/package limit.
The existing upstream SVG/record bounds still apply. Every stored package read,
approval/export and artwork retrieval must resolve current evidence again.

STOP ALL ON; external lock ON; automation OFF; Manual orders; RELEASE HOLD.
Technical fixture artwork and synthetic test evidence are not commercial approval.

## Exact bounds and reference integrity

Existing inline SVG60000-byte and structured input/package65536-byte limits remain.
The explicit reference path resolves existing upstream SVG262144-byte/record400000-
byte storage, checks original record hash/approval and SVG checksum, and projects
the record WITHOUT SVG into the package. Projected record.version_hash denotes
the original full durable record, not a hash of the projected JSON. It is labeled
as projected; package seal binds the projection and immutable original reference.

Internal package-version records are explicitly bounded196608 bytes because they
retain both input evidence and compiled snapshots. Final export including native
and commercial sidecar metadata still must fit65536 bytes or returns a held error.
SVG attachment retrieval is authenticated and checksum-verified; it is never
embedded into inline HTML. Unrelated filesystem paths are not accepted anywhere.
Larger metadata still fails closed. No silent truncation, rescaling or limit lift.

Supplemental PNG references and metadata remain in the commercial sidecar;
the current A3 handoff revalidates their bytes on reads. Retrieve via A's authenticated
raster(shop, designHash, reference), not a path/URL. Any supplemental rasters retain
SUPPLEMENTAL_RASTER_COMPOSITION_REVIEW_REQUIRED; no inferred vector/PNG print parity.
