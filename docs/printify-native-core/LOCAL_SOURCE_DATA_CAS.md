# Local protected source-data CAS — not complete authorization CAS

This additive source component remains offline and non-authorizing. The ordinary IMAGE source1.0 and PRICE source1.0 response shapes remain unchanged. No canonical native mutation capability, version counter, dispatch lease, independent epoch or recovery guarantee is issued.

Existing protected business getters report only the exact option name, presence and SHA-256 of the raw bytes they actually read. Raw source bytes are not retained in the manifest. Fixed business-data prefixes, including the exact validated supplier mockup records read during export, are accepted; credential, token, authorization and unrelated option names are rejected. Captures are bounded to96 roots/64MiB of unique observed bytes. Differing observations of one root invalidate the capture. No cache, caller-supplied query or SQL replay is used.

The independently reviewed mutation-association source now binds this opaque dependency map. Its existing approval transaction locks and compares each exact unique option-name row, including a missing decision pointer's insertion gap, before writing its own producer audit. Real InnoDB/REPEATABLE READ and existing strict durability requirements remain mandatory. This helper neither starts nor commits/rolls back the caller's transaction. Drift denies approval; cancellation/revocation can still proceed after source invalidation.

Compatibility: adding dependency metadata changes association source/proposal hashes. Earlier source reviews must fail stale and require explicit new proposal plus distinct current reviewer approval. There is no automatic renewal, migration or inferred permission. Normal source evidence/hash formats and companion PRICE read schema are preserved.

The preceding artwork closure additionally locks exact asset-spec, required plan-asset linkage and latest spec/link approval ranges, with existing actual business dependency locks.

These guarantees cover observed business/artwork/data roots only. Authority, current session, global-owner lifecycle, delegation/roles, provider connection/policy and all independent recovery roots are not collectively locked by this component. Consequently source_approval_cas_verified remainsfalse, native_product_version remainsnull and dispatch/external execution remainfalse. Local concurrency tests are not hosted crash-durability or all-root rollback certification.

Final transaction checks bind the original wpdb object and physical CONNECTION_ID and require the caller transaction to remain active with the same strict RR/durability predicates after material reads and immediately before the association producer audit. Normal connection loss/reconnect or an ended transaction denies. This is not proof against an arbitrary malicious in-process callback deliberately ending and replacing transactions; no complete authority CAS or external execution permission is inferred. A full single-column UNIQUE option_name index is required before narrow option row/gap fences are claimed. Oversized/invalid observations are rejected before raw-byte hashing.

Source-specific approval acknowledgement also requires the exact current approved stream plus its original durable producer receipt against the already validated final source; the stream is checked again afterward. A normal reconnect that rolls back the producer but allows generic approval persistence is reported as approval UNKNOWN, never a successful source approval or automatic retry. This adds no extra full source scan or generic review store.
