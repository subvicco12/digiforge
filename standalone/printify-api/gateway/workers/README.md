# Protected GET gateway Workers target

This is an undeployed ES module and Durable Object adapter, exercised with Node 24.19 and a PHP 8.4.27 fixture bridge to the exact packaged contracts. It requires Workers Web APIs, a SQLite-backed Durable Object supporting storage transactions, and private service bindings. No npm runtime dependencies. The PHP bridge and file-backed sequencer are local test harnesses. Neither qualifies Cloudflare runtime behavior.

## Trust and ordering

The public Worker returns 404. The Durable Object accepts only the explicit offline-fixture mode. The template sets held mode. A future private ingress must authenticate WordPress instance and current operator session before issuing a short-lived signed grant. The exact request and grant bind operation, selector, account, shop, integration, actor, session and profile revision. Quota uses a stable site/account/shop/integration digest. No operator setting controls the gate.

- CONTRACTS verifies the full typed request and Ed25519 grant, returning exact digests and path. It projects bounded JSON through the reviewed endpoint-specific validators. The Worker independently reconstructs the fixed Printify HTTPS route and checks it before handoff. Provider URLs and continuation links from responses are unused.
- POLICY returns the current independent epoch, sequence, release state, revocations and policy revision. After the local transaction consumes the grant and charges quota, the policy service must atomically compare/advance the independent floor with STOP and revocation checks and bind the returned checkpoint to the exact request, scope and grant. If either write or acknowledgment is uncertain, deny and preserve the discrepancy. Before returning observations, the service must confirm that release is still permitted. A policy transition after admission may suppress release while the admitted read is in flight. Cloudflare storage alone cannot prove rollback resistance.
- FIXTURE_CUSTODY receives only a fixed HTTPS GET, exact account/shop/integration and opaque custody reference, body and time limits, and admission identity. The fixture binding returns synthetic responses. A future production custody service must independently validate admission, use the least-privilege credential, reject redirects, verify TLS, honor egress and size/time controls, and preserve redacted audit evidence. No credentials or direct Internet fetch exist in this module. It never sends a raw provider body to WordPress.
- REPLY_SIGNER signs the same correlated v1 reply reviewed by the standalone verifier. Its dedicated key must stay outside WordPress. Policy, custody and signing trust are deployment prerequisites, not additional roles delegated to the plugin.

## Minimal setup after separate authorization

Allocate one admission object per approved stable scope. Provide a reviewed process to initialize its head against the external epoch and floor, with no auto-init on missing or mismatched state. Initialize a reviewed quota and controlled epoch transition policy. The adapter currently admits at most 100 reads per initialized epoch and retains consumed grant identities until a separately authorized epoch transition. Select independently governed policy/floor, custody, typed-contract and signer services and provide binding identities without adding secrets to this template. Confirm account entitlement, private routes, observability and spend boundaries. Qualify runtime, STOP/drain, revocation, outage, acknowledged and ambiguous restores, and exact WordPress coexistence before proposing a read-only pilot. Preserve current holds and exclude mutations.

`node --test --test-isolation=none standalone/printify-api/gateway/workers/worker.test.mjs` runs the adapter unit checks. Set `DF_PROTECTED_GET_WORKERS_FIXTURE=1` when running the existing disposable `protected-get-wordpress.php` harness to exercise the same ten WordPress read flows through the Workers-target module. The runner uses a single process per interaction and an independent synthetic floor file. It is not a multi-host emulator.
