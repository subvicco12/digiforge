# Protected GET v1 offline reference

WordPress can perform a manual exchange only in the explicit local printify_fixture workspace with a pinned fixture response key. The fixture gateway and synthetic private keys are outside the plugin ZIP. The gateway accepts a typed GET intent, a short-lived Ed25519 grant bound to the canonical intent digest, and a current independent fixture policy snapshot. Its bounded journal uses a stable local lock, fsync and atomic rename. Access requires an explicitly initialized private journal. Missing state fails closed. The fixture exchange returns a correlated signed synthetic receipt without HTTP. STOP and revocation are rechecked around admission and after the fixture response. The independent policy callback does not share the journal transaction. This model does not qualify cross-domain atomic policy ordering, power-loss recovery or resistance to restoration of an older journal.

A production transport needs authenticated peer identity, a trusted grant issuer and current policy, credential custody outside WordPress, signed correlated responses, a fixed provider origin and disabled redirects, durable atomic grant admission and quotas, timeouts, body limits, and independent STOP and drain qualification. Its policy must reject requests under the current release hold. A Worker is a candidate deployment target if the account and operator boundary are independently approved. A single durable authority must own admission and revocation ordering. Worker environment secrets are acceptable for provider credentials only if independently governed access and rotation are proven. Cloudflare entitlement, credential scopes and production identity are unverified. There is no deployable Worker or live provider adapter in this change.

Run the extracted-package fixture from the repository with `php standalone/printify-api/tests/protected-get.php /path/to/digiforge-printify-api`.

For a Cloudflare reference, keep grant consumption and quota in one Durable Object or equivalent serialized authority per approved scope. Policy transitions must participate in that ordering before any external effect. Keep key custody and provider egress separately governed. Workers KV is unsuitable as the admission authority. Use explicit epoch and recovery rules before admitting reads after uncertain restore. No cloud resource is created by this reference.
